## Start your docs

This is a documentation boilerplate built with Fumadocs, TanStack Start, and Vite. It provides the shared Anyway design, MDX pages, search, navigation, and interactive examples. Replace the sample content with documentation for your project.

From the repository root:

```bash title="Terminal"
bun install
bun run dev:docs
```

Open [localhost:3007](http://localhost:3007). Changes to pages and previews appear as you work.

## Create a project copy

To keep this starter alongside another documentation app, create `apps/my-project-docs` and copy these files from `apps/docs`:

- `content/`, `public/`, `src/`, and `tests/`
- `package.json`, `source.config.ts`, `tsconfig.json`, and `vite.config.ts`

Leave out generated files and build output: `node_modules/`, `.source/`, `.tanstack/`, `dist/`, and `src/routeTree.gen.ts`. Rename the package in its `package.json`, then run from the workspace root:

```bash title="Terminal"
bun install
bun run --cwd apps/my-project-docs dev --port 3008
```

Use a different port when running both documentation apps at once.

<Callout className="docs-callout" title="Workspace starter">
The package uses this repository’s Bun dependency catalog. For a different repository, copy the matching catalog entries from the root `package.json` or replace `catalog:` references with concrete versions. The optional Switch example also uses a local workspace package; [remove it](#keep-or-remove-the-switch-demo) if your project does not include that package.
</Callout>

## Configure your project

Edit `src/docs.config.ts` to supply your project’s identity and destinations:

| Setting | What it controls |
| --- | --- |
| `name` and `description` | Site metadata, brand labels, and the search breadcrumb |
| `logo` | A monochrome asset in `public/`, its dimensions, and its visual baseline |
| `repositoryUrl` | The header’s GitHub link |
| `homePage` | The default docs slug and error recovery destination |
| `navigation` | Section labels, icons, and destination slugs |
| `hero` | The banner headline and action labels, slugs, and optional heading hashes |

Slugs are relative to `/docs/`, such as `getting-started` or `components`. Keep page text and navigation ordering in the content files. The shared shell preserves the typography, paper texture, theme switch, and ink behavior.

## Write your first page

Create an `.mdx` file under `content/docs`. Give it a title and description, then write in Markdown:

```mdx title="content/docs/your-page.mdx"
---
title: Your first guide
description: Explain one useful thing your project can do.
---

## Start here

Write the steps your reader needs.
```

This page appears at `/docs/your-page`. Add `your-page` to the nearest `meta.json` to choose its position. The `...` entry includes remaining pages automatically. Headings populate the page outline, and the content is included in search.

| Location | What belongs there |
| --- | --- |
| `content/docs/` | MDX pages and `meta.json` navigation files |
| `src/docs.config.ts` | Project branding and shared destinations |
| `src/components/` | Documentation shell and shared MDX components |
| `src/examples/` | Page-specific React previews |
| `src/styles.css` | Shared documentation design tokens and styles |
| `public/` | Fonts, branding, and other static assets |

## Add a live example

Create a React component in `src/examples/` and import it directly into the MDX page that uses it. Keep the explanation in MDX and the interactive state in the component.

The [Live examples guide](/docs/components) includes a working counter and the import pattern. Load product styles and providers inside the example, so removing a demo does not change the shared documentation shell. Components used across many pages can be registered in `src/components/mdx.tsx`.

## Keep or remove the Switch demo

The macOS Switch is an optional sample of a richer playground. Keep it to explore controls, generated code, and accessibility guidance, or remove it when you replace the sample content.

To remove it from your copy:

1. Delete `content/docs/components/switch.mdx`.
2. Delete `src/examples/switch/`, including its playground, code generator, and tests.
3. Remove `@anyway-design/macos` from that app’s `package.json` dependencies.
4. Run `bun install` from the workspace root to update the lockfile, then run the checks below.

No shared layout or style edits are needed. Navigation discovers the remaining example pages automatically, and the Examples tab and banner action continue to open the general examples guide.

## Build and publish

For your project copy, run these checks from the workspace root:

```bash title="Terminal"
bun run --cwd apps/my-project-docs build
bun run --cwd apps/my-project-docs check-types
bun run --cwd apps/my-project-docs test
```

Use `apps/docs` instead if you are working directly in the starter. Build first on a fresh checkout so Fumadocs and TanStack can generate their files. Before publishing, check your branding, navigation, search, and examples on desktop and a narrow screen in both themes.

Deployment is not configured in this starter. Choose hosting that supports the TanStack Start server build and configure its adapter before publishing; the search endpoint also runs on the server.
