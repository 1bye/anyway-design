## Add your own

Create a component under `src/examples/`, then import it directly into the MDX page that uses it:

```mdx title="content/docs/your-page.mdx"
---
title: Your example
description: Explain the behavior, then let the reader try it.
---

import { CounterExample } from "../../src/examples/counter";

<CounterExample />
```

The import is relative to the MDX file. A page inside another folder, such as this one, uses `../../../src/examples/counter` instead.

Keep each example’s state inside its component. Import any product styles from the example itself, and wrap its preview in the providers that product needs. Shared documentation styles and providers belong to the shell.

For components used throughout the documentation, add them to `src/components/mdx.tsx` instead of repeating an import in every page.

## Replace the sample content

Keep the examples that help explain your project. Remove sample MDX pages and their matching source files when you no longer need them. The Examples navigation and hero action point to this overview, so they keep working as individual demos come and go.

The optional macOS Switch demo is one example of a richer playground. Its removal steps are in [Getting started](/docs/getting-started#keep-or-remove-the-switch-demo).
